# 阶段三：内容生成能力接入实施计划

> **实施窗口：2026-08-17 ~ 2026-08-21**  
> **启动记录：2026-08-06**  
> **依据：**《智能体项目开发流程计划》阶段三、《市场部智能体项目建设方案》以及当前阶段二验收记录。  
> **执行边界：**Dify 继续负责知识库、检索、Workflow 编排和生成节点；本仓库不保存资料原文、提示词中的敏感内容、凭据、真实地址或生成文件。阶段二已发布版本保持不变。

## 0. 当前约束与目标

阶段三的目标是让市场部可以基于已审核的知识库证据，生成以下五类内容：

1. 结构化项目/产品文档；
2. PPT 大纲和逐页内容要点；
3. 公众号文章；
4. 视频号脚本和销售话术；
5. 文生图结果。

当前执行约束如下：

- IMA 笔记联通继续暂缓，不作为阶段三前置条件。新增资料直接导入 `.md`、Word `.doc/.docx` 或 `.pdf` 文件，且必须遵守阶段二收录规则。
- 阶段三验证优先沿用阶段一已导入、阶段二已验证的 5 份 P1 正式资料；不新增、不复制、不上传占位测试文件。
- `phase2-routing-v1` 及其已发布版本不修改、不覆盖。阶段三创建独立的 draft/application 或独立 Workflow；共享知识库可以读取，但不能为了生成测试改变 P1/P2/P3 元数据或路由连接。
- 阶段二真实 P2 命中仍是待真实资料进入后的补测项，不得用阶段三生成结果替代该验收。
- 阶段二验证当时曾因无可用 LLM channel 采用证据直出；2026-08-06 阶段三现场确认 `gpt-5.6-luna` 实际调用返回 `503 model_not_found`，已改用可调用的 `gpt-5.6-sol` 完成独立 Workflow 文本验证。文生图工具尚未发现，不得把文本结果冒充图像生成。

已创建独立、未发布的 `phase3-image-generation-api2img` Workflow，且未改动 `phase2-routing-v1`。草稿固定为三节点链路：必填文本输入 `prompt` → HTTP 图像生成请求 → 输出 `image_response`。请求采用 GPT Image 2 的单图 JSON 契约，参数为 `size=auto`、`quality=medium`、`output_format=jpeg`、`output_compression=50`；鉴权通过 Dify Secret 环境变量持久配置，密钥、地址和请求原文未写入仓库或本地配置。

## 2. 方案边界

### 2.1 生成 Workflow 的职责

创建独立的 `phase3-content-generation` draft，输入和输出保持结构化，便于后续接入 API 或模板转换：

| 输入 | 类型 | 必填 | 用途 |
|---|---|---:|---|
| `request` | String | 是 | 当前内容任务；不在仓库记录真实问题原文 |
| `content_type` | String | 是 | `document`、`ppt`、`wechat_article`、`video_script`、`sales_talk` 或 `image_prompt` |
| `audience` | String | 否 | 目标读者、客户或内部使用对象 |
| `tone` | String | 否 | 正式、专业、简洁等风格约束 |
| `length` | String | 否 | 输出长度或页数范围 |
| `source_scope` | String | 否 | 默认使用已登记的知识库范围；不得传入凭据或敏感配置 |

推荐的节点边界为：

```text
Start
  -> Validate Request
  -> Retrieve Approved Evidence
  -> Normalize Evidence
  -> Evidence IF
       false -> Insufficient Evidence Answer
       true  -> Content Type IF / Router
                   -> LLM prompt for the selected content type
                   -> Validate Generated Structure
                   -> Answer or File/Image Output
```

生成 Workflow 只使用已批准的知识库证据。没有有效证据时，返回需要补充资料的结果，不根据模型常识补写公司事实。联网资料如需使用，应沿用阶段二的 Web 证据边界并显示来源；不能把 Web 结果伪装成封闭知识库内容。

### 2.2 五类内容的最低输出契约

| 内容类型 | 最低可验收输出 | 质量约束 |
|---|---|---|
| 文档 | 标题、摘要、背景/现状、核心内容、结论或下一步、证据标记 | 结构完整，事实来自有效证据，输出可复制到 Markdown/Word 模板 |
| PPT | 总体主题、页数、每页标题、每页 3~5 条要点、结尾页行动项 | 页面层级清楚，不能只返回一段文章；页数约束可解释 |
| 公众号文章 | 标题、导语、分段正文、小标题、结尾行动引导 | 语气适合公众号，区分事实与推断，不泄露内部敏感信息 |
| 视频号脚本 | 镜头/段落、口播、画面提示、时长或节奏、结尾行动引导 | 适合口播，句子短，画面与口播可对应；不依赖阶段四的 ASR/TTS |
| 销售话术 | 客户场景、开场、价值说明、异议处理、行动引导 | 可直接使用或少量修改，不能编造产品能力、案例或承诺 |
| 文生图 | 图像提示词、尺寸/比例、风格和禁用项；若能力可用则返回图像资产 | 图像任务不把文字答案当作生成成功；保留生成状态和失败原因 |

`.docx`、`.pptx` 等二进制文件是否能由当前 Dify 环境直接导出，必须以 G0-5 现场能力为准。若只有文本输出，阶段三先验收结构化内容；模板转换或文件下载作为明确的后续接入项，不在没有可用节点时伪造完成。

## 5. 失败处理、权限和回滚

- LLM channel 无可用通道：停止真实生成运行，检查 provider、模型启用状态、workspace 配额和调用权限；保持阶段二证据直出版本不变。
- 生成节点或插件失败：记录节点、状态、失败原因和测试编号；只重试失败任务，不重复导入知识库资料。
- 检索结果为空或无法规范化：走证据不足分支；不得让 LLM 用常识补齐内部事实。
- 生成内容结构不合格：修正独立 Workflow 的模板/校验节点，保留上一版 draft；不回写阶段二 Workflow。
- 图像或文件生成插件权限不足：记录权限缺口，不能把提示词或文本响应标为资产成功。
- 任何结构修改前保存 draft/hash；发生回归时恢复阶段三上一版 draft。阶段二版本只做只读回归核对，不在阶段三中恢复或重新发布。
- 任何凭据、真实地址、内部资料原文和生成文件均不写入仓库或计划文档。
