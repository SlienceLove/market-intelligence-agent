# 阶段四：多模态自研模块开发实施计划

> **日期：** 2026-08-07  
> **阶段窗口：** 2026-08-24 ~ 2026-09-04  
> **目标：** 在现有 .NET 8 模块化基座上，按“采集 → ASR → OCR → TTS → 视频合成”的顺序建立可测试的多模态能力边界，并为 Dify 提供受控的 HTTP 调用入口。

## 1. 背景与边界

阶段三已经完成五类结构化文本输出：`document`、`ppt`、`wechat_article`、`video_script` 和 `sales_talk`。其中 `video_script` 的口播文本、画面提示、段落顺序和目标时长将作为本阶段视频处理链的上游输入。

本阶段继续保持以下边界：

- Dify 仍负责对话、知识库、RAG 和 Workflow 编排；本仓库只实现 Dify 不直接提供的扩展能力。
- IMA 笔记联通继续跳过。后续资料仍直接导入 `.md`、Word `.doc/.docx` 或 `.pdf`，不在本阶段实现 IMA 直连或同步。
- 不修改或重新发布 `phase2-routing-v1`；阶段二的 22 节点/22 边基线只做只读回归核对。
- 不把阶段三的文本结果冒充音频、图片或视频资产；每种媒体输出必须有明确的资产引用、媒体类型和处理状态。
- 视频号采集只支持获得授权、符合平台条款和适用法律的来源。不得绕过登录、验证码、访问控制、反爬策略或付费限制；无法确认授权的来源只返回受控失败。
- 测试不写入真实问题原文、敏感资料、完整生成内容、真实凭据或媒体文件。测试使用伪造元数据、短小本地 fixture 和 fake adapter。

现有 `.docx/.pptx` 导出与文生图能力仍是阶段三的后续接入项，不阻塞本阶段的音视频链路开发。

## 2. 目标架构

保持现有解决方案的依赖方向：

```text
Dify Workflow / 内部调用方
            |
            v
      Api（鉴权、校验、作业入口）
            |
            v
 Application（用例、接口、领域契约）
            |
            v
 Infrastructure（HTTP provider、FFmpeg、临时存储）
            ^
            |
 Worker（可取消的异步作业与后续调度）
```

应用层只依赖稳定接口和领域契约，不引用 provider SDK、FFmpeg 进程模型或具体采集实现。基础设施层负责外部调用、超时、重试、凭据读取和输出映射。API 和 Worker 复用同一组应用用例。

所有长任务都携带：

- `correlation_id`：贯穿请求、日志和作业状态；
- `idempotency_key`：避免 Dify 重试造成重复采集、合成或投递；
- `cancellation_token`：请求取消或 Worker 停止时及时终止；
- `status`、`failure_code` 和安全的 `failure_message`：便于运维复核，不写入凭据或原始敏感内容。

## 3. 统一契约

### 3.1 作业与资产

建议在 `MarketIntelligence.Agent.Application` 中建立 provider-independent 契约：

| 契约 | 关键输入 | 关键输出 | 约束 |
|---|---|---|---|
| `MediaJobRequest` | 作业类型、输入资产引用、参数、关联 ID | 规范化作业对象 | 拒绝空引用、超限参数和不支持的媒体类型 |
| `MediaJobResult` | 作业 ID、状态、错误信息 | `succeeded`/`failed`/`cancelled`、输出资产引用 | 不在响应中返回完整媒体二进制 |
| `MediaAssetReference` | 受控 URI 或临时存储键、媒体类型、大小、时长 | 可供下一模块消费的引用 | 不允许把仓库路径或凭据放入外部响应 |
| `TimedTextSegment` | 起止时间、文本、置信度 | ASR/OCR 可合并的时间轴片段 | 起止时间必须合法，文本按安全规则截断 |

输入校验应在调用 provider 前完成；失败请求不得产生外部网络请求、FFmpeg 进程或持久化媒体。

### 3.2 模块接口

在应用层定义以下最小接口，具体命名可随实现保持一致但不得把 provider 类型泄漏到应用层：

```text
IChannelMediaCollector
ITranscriptionService
IFrameOcrService
ISpeechSynthesisService
IVideoCompositionService
```

每个接口都返回统一的 `MediaJobResult` 或等价的强类型结果，并支持 `CancellationToken`。provider 选择通过配置和依赖注入完成，不在业务用例中写死模型名、端点或 API key。

## 4. 按顺序实施的任务

### M4-00：基座、契约和能力检查

**目标：** 在实现外部适配器前固定模块边界，避免把未经确认的服务绑定到代码中。

- [x] 复核 .NET SDK、现有五项目依赖图、`/health` 合约和 Worker 启动行为。
- [x] 增加媒体领域契约、错误分类、配置选项和输入校验，不添加真实 provider SDK 或凭据。
- [x] 记录本机未安装 FFmpeg；未安装时保留可替换的 `IProcessRunner`，不在测试中依赖本机状态。
- [ ] 确认 ASR/OCR/TTS provider 的授权、区域、数据留存和配额要求；没有明确授权时只实现接口和 fake/contract adapter。（部分完成：ASR/OCR 已定为本地方案并完成 sidecar 验证；TTS 音色商业授权待确认）
- [x] 保存阶段二和阶段三的只读基线：`phase2-routing-v1` 为 22 节点/22 边，`phase3-content-generation` 保持独立 draft。

**验收：** 解决方案可恢复、构建；应用层没有外部调用；配置缺失时服务能启动但相关能力返回明确的 `provider_not_configured`。

### M4-01：视频号链接采集模块（08-24 ~ 08-26）

**目标：** 对授权来源进行安全的链接规范化、元数据获取和资产登记，为后续媒体处理提供可追踪输入。

- [x] 定义来源类型、允许的 URL 规则、最大响应大小、连接/读取超时、重定向上限和速率限制。
- [x] 实现 URL 解析与规范化；拒绝非 HTTP(S)、本地文件、内网地址、异常端口、过大的重定向链和未经允许的域名。
- [x] 通过 `HttpClient` 或获批准的浏览器适配器访问允许来源；不实现验证码破解、登录态窃取、指纹伪装或反爬绕过。
- [x] 将标题、作者标识（脱敏或哈希）、发布时间、媒体类型、时长和来源引用映射为安全元数据；原始页面内容不进入日志或仓库。
- [x] 使用幂等键登记采集作业，重复请求返回已有作业状态，不重复下载媒体。
- [x] 对拒绝、超时、429、403、响应过大、媒体类型不符和解析失败分别返回稳定错误码。

**当前状态：** 仅通过本地 mock HTTP 验证，未访问真实平台；真实授权来源 smoke test 仍为后续项。

**验收：** 合法的本地 mock HTTP 来源可完成元数据流程；所有拒绝场景在外部调用前或受控边界内失败；测试证明不存在反爬绕过逻辑。

### M4-02：ASR 语音转文字（08-27 ~ 08-28）

**目标：** 将已登记的音频或视频资产转换为带时间轴的文本片段，并保留 provider 置信信息。

**Provider 决策：** 默认优先本地 `faster-whisper` 适配器；阿里云、腾讯云或火山引擎 ASR 仅在完成授权、区域、数据留存和配额确认后作为云备选；OpenAI transcription 只用于质量基准，不让应用层绑定具体模型名或凭据。

- [x] 定义音频格式、大小、时长、语言、分段和置信度的规范化模型。
- [x] 实现 provider-independent `ITranscriptionService` 和基于 `HttpClient` 的适配器；凭据只从环境变量或本机 secret store 读取。
- [x] 对 4xx 永久失败、429 限流、5xx 临时失败、超时和取消进行不同分类；只对安全的临时失败执行有上限的指数退避。
- [x] 将 provider 返回的时间戳统一为毫秒或 `TimeSpan`，校正重叠/倒序片段，并限制单段文本和总文本长度。
- [x] 日志只记录作业 ID、语言、时长、片段数量和状态，不记录完整转写文本或音频内容。

**当前状态：** `faster-whisper/base` CPU `int8` 已通过本地 sidecar 的 API → 队列 → adapter 全链路 smoke；真实部署与授权真人语料验收为后续项。

**验收：** fake provider 成功、空结果、格式错误、限流、超时和取消用例均通过；应用层测试不发起真实网络请求。

### M4-03：OCR 截图文字识别（08-31）

**目标：** 从视频帧或授权图片中提取可用于字幕/内容整理的文字区域。

- [ ] 定义帧采样策略：间隔、最大帧数、最大分辨率、重复帧去重和处理总时限。（部分完成：间隔、最大帧数、最大时长和超时已定义；最大分辨率与重复帧去重待补）
- [x] 定义 OCR 结果模型：帧时间、文本、边界框、语言、置信度和 provider 状态。
- [x] 实现 `IFrameOcrService` 与 provider adapter；图片只通过受控临时引用传递，不写入仓库或普通日志。
- [x] 对低置信度、空文本、图片过大、格式不支持和 provider 不可用情况返回可区分状态；不得把 OCR 推测当作事实证据。
- [x] 仅保留完成后续任务所需的最小元数据，并提供临时文件清理和失败清理路径。

**当前状态：** RapidOCR / PaddleOCR ONNX 单图片 sidecar 已通过 API → 队列 → adapter 全链路 smoke。`IVideoFrameSampler` 目前只有接口和参数构建器，尚无真实实现，视频帧上游未接入服务层。

**验收：** 使用小型脱敏 fixture 验证帧采样、去重、坐标映射、置信度和清理行为；provider 失败不会留下孤立临时文件。

### M4-04：TTS 语音合成（09-01 ~ 09-02）

**目标：** 将阶段三脚本中的口播文本转换为可供合成的视频音轨，并保留音频时长和片段对应关系。

- [x] 定义 voice、language、语速、音调、格式、采样率和总时长限制；不允许调用方任意传入未批准的声音或模型。
- [x] 按 provider 限制切分文本，保证切分不破坏句意，并为每段建立稳定顺序和关联 ID。
- [ ] 实现 `ISpeechSynthesisService`、响应映射、临时音频引用和拼接前的时长校验。（部分完成：契约与 fake service 已就位；无 Infrastructure HTTP adapter，DI 仍解析到 `UnconfiguredSpeechSynthesisService`）
- [ ] 对敏感输入、超长输入、限流、余额/配额错误和 provider 未配置给出安全失败；不在日志中保存完整口播稿。（部分完成：未配置与输入边界已覆盖；限流与配额分类待真实 adapter）
- [ ] 明确音频格式、许可证、声音使用权限和数据留存策略；未获批准的声音不进入验收。

**当前状态：** sherpa-onnx 中文 VITS 本地基准已完成，`zh-ll` 优于 AISHELL3。阻塞点为音色商业授权与人工试听，非工程实现；`scripts/media/` 下尚无 tts sidecar。

**验收：** fake provider 的分段、顺序、失败重试、取消和输出引用用例通过；输出只登记资产引用和摘要元数据。

### M4-05：视频合成与音画同步（09-03 ~ 09-04）

**目标：** 使用受控 FFmpeg 进程把授权视频、TTS 音轨、字幕/画面提示和可选片段合成为输出视频。

- [ ] 定义合成时间线：视频片段、口播音频、字幕片段、静音填充、裁切策略、目标分辨率和编码格式。（部分完成：视频/音频输入、`-shortest`、H.264/AAC 编码已定义；字幕片段、静音填充、裁切策略和目标分辨率待补）
- [ ] 实现安全的 FFmpeg 参数构建器和 `IProcessRunner`；使用参数数组/无 shell 调用、允许列表、超时、取消和输出大小限制。（部分完成：参数构建器已就位并使用参数数组；`IProcessRunner` 只有 `FakeProcessRunner`，无真实进程实现）
- [x] 在启动前校验输入资产引用和输出目录；禁止将用户输入直接拼接为命令行或路径。
- [ ] 采集退出码、标准错误摘要、输出时长和音画偏移；对超时、非零退出、输出为空和音频时长不匹配返回稳定错误码。（部分完成：退出码/超时/取消分类已在契约层；输出时长与音画偏移需真实 runner 与 ffprobe）
- [ ] 在成功和失败路径清理临时中间文件；最终资产只通过受控引用返回。（部分完成：资产引用已受控；临时文件清理需真实实现）
- [x] 如本机未安装 FFmpeg，保留 fake runner 的完整测试，真实合成只在具备工具和授权素材时做单独 smoke test。

**当前状态：** FFmpeg 已通过用户范围 `Gyan.FFmpeg.Essentials 8.1.1` 安装，抽帧 smoke 通过，但该验证绕开 .NET 服务层、由临时脚本执行。参数构建器产出的 `asset://` / `fixture://` URI 与相对输出路径无法被真实 ffmpeg 解析，需在 Infrastructure 层建立受控资产路径解析。真实音画合成待授权音频验证。

**验收：** 命令构建、路径安全、取消、超时、失败清理和时间线校验均有自动化测试；真实 smoke test（若环境具备）只记录状态、时长和偏移，不提交视频文件。

## 6. 安全、权限与数据留存

- 采集、ASR、OCR、TTS 和 FFmpeg 均使用最小权限；provider key、服务间 key、数据库连接串和 webhook secret 不进入仓库。
- 所有外部 URL、重定向、媒体大小、分辨率、时长、帧数、文本长度和并发数均设上限。
- 临时媒体放在明确的临时目录，设置清理策略和失败清理；仓库不存放音频、图片、视频、截图或模型文件。
- 日志采用结构化字段，禁止写入 token、完整音视频内容、完整 ASR/OCR/TTS 文本和未经脱敏的来源参数。
- 对真实平台采集遵守服务条款、版权、隐私和适用法律；没有授权的来源不进入测试或生产链路。
- 任何 provider 失败都只影响当前作业，不阻塞 Dify 其他 Workflow 或阶段二路由。

## 7. 阶段验收与交接

阶段四完成的最低条件：

1. 五个模块都有应用层接口、基础设施适配边界、稳定错误分类和自动化测试。
2. API/Worker 能安全受理、查询、取消和幂等处理长任务；未配置 provider 时不会假成功。
3. ASR/OCR/TTS 的输出可被 FFmpeg 合成用例消费，时间轴、资产引用和失败状态保持一致。
4. 所有正常测试不调用真实平台；真实 smoke test（如获授权）与自动化测试分离。
5. `phase2-routing-v1` 与阶段三 draft 未被修改；IMA 仍为暂缓项。
6. 文档记录 provider 授权、FFmpeg 环境、数据留存、失败项和后续接入项，不记录真实凭据或业务原文。

交接给阶段五时，至少提供：

- 视频资产引用、采集元数据和授权状态；
- ASR 时间轴文本与置信度；
- OCR 帧文本、坐标和置信度；
- TTS 音频引用、时长和分段关系；
- 合成视频引用、编码信息、时长和音画偏移；
- 每个作业的状态、错误码、关联 ID、幂等键和复核时间。

## 8. 明确的后续项

以下事项不作为阶段四完成条件：

- IMA 自动同步到 Dify；
- 文生图 provider 和图像资产验收；
- Dify 原生 `.docx/.pptx` 导出或模板转换；
- 未获得授权的平台登录态采集、反爬绕过和批量抓取；
- 生产级 PostgreSQL/对象存储/队列部署和永久启动配置。

这些事项应在具备授权、provider、部署环境和独立验收标准后单独立项。
